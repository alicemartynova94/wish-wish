# Discovery

## Постановка проблемы
Большинство пользователей не хотят регистрироваться в новом сервисе только для того, чтобы забронировать подарок из чужого wish list.
Текущий подход создаёт дополнительный барьер для пользователей, которые не планируют регулярно пользоваться сервисом.

## Бизнес-цель

Создать сервис wish-wish, который позволяет пользователям совместно управлять списками желаемых подарков и предоставляет возможность резервировать подарки без обязательной регистрации.

## Stakeholders

### Business Owner
Владелец продукта, определяющий бизнес-цели, ограничения и правила монетизации сервиса.

### Wishlist Owner
Пользователь, создавший wish list и являющийся его владельцем.

### Wishlist Editor
Пользователь, которому владелец предоставил права на редактирование wish list.

### Gift Giver
Пользователь, который просматривает wish list и резервирует подарок. Регистрация для резервирования не является обязательной.

## Первоначальные допущения

### Q-001
Пользователь, резервирующий подарок без регистрации, может создать аккаунт.  
Статус: Принято.
### Q-002
Владелец wish list может самостоятельно включать или отключать уведомления о бронировании подарков.  
Статус: Принято.
### Q-003
Информация о личности пользователя, забронировавшего подарок, не отображается владельцу или редакторам wish list.  
Статус: Принято.
### Q-004
Статус: открыто для уточнения. 
### Q-005
Пользователь может забронировать неограниченное количество подарков.  
Статус: Принято.
### Q-006
Редактор может добавлять новые подарки, редактировать название и описание подарков, возможно удалять подарки.  
Статус: открыто для уточнения.  
Решение: необходимо определить, может ли редактор удалять подарки.
### Q-007
Статус: Открыто для уточнения.
Решение: необходимо определить, может ли у одного wish list быть более одного владельца. 
### Q-008
Редактор добавляется владельцем wish list с помощью специальной ссылки-приглашения.  
Статус: Принято.
### Q-009
После создания брони незарегистрированный пользователь получает уведомление на указанный email, по ссылке из письма он может управлять своей бронью и отменить её в течение 15 дней.  
Статус: Принято.
### Q-010
Бронь подарка действует бессрочно до архивации wish list.  
Статус: Принято.
### Q-011
Неактивный wish list должен переходит в архив через 3 месяца с даты создания.  
Статус: Принято.
### Q-012
Владелец может удалить wish list.  
Статус: Принято.
### Q-013
Пользователь может бесплатно создать до 5 wish list.  
Статус: Принято.

## Scope

### In Scope
* создание и управление wish list;
* добавление и редактирование подарков;
* совместное управление wish list;
* роли владельца и редактора;
* публичный доступ к wish list;
* резервирование подарков без регистрации;
* управление и отмена гостевой брони;
* уведомления;
* правила видимости информации о бронированиях;
* архивирование и удаление wish list;
* ограничения бесплатного тарифа.
### Out of Scope
* мобильное приложение;
* платёжная инфраструктура и реализация оплаты; 
* администрирование системы.
