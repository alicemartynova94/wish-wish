# Функциональные требования

## Аутентификация и управление пользователями

### FR-001
Система должна позволять пользователю зарегистрировать учётную запись.

### FR-002
Система должна позволять зарегистрированному пользователю входить в систему и выходить из системы.

## Управление wish list

### FR-003
Система должна позволять зарегистрированному пользователю создать wish list.

### FR-004
Система должна позволять владельцу wish list редактировать информацию о wish list.

### FR-005
Система должна позволять владельцу wish list удалить wish list.

### FR-006
Система должна позволять владельцу wish list архивировать wish list.

## Совместное управление wish list

### FR-007
Система должна позволять владельцу wish list пригласить пользователя в качестве редактора с помощью ссылки-приглашения.

### FR-008
Система должна позволять приглашённому пользователю принять или отклонить приглашение стать редактором wish list.

### FR-009
Система должна позволять владельцу wish list удалить редактора из wish list.

## Управление подарками

### FR-010
Система должна позволять владельцу или редактору wish list добавлять подарок в wish list.

### FR-011
Система должна позволять владельцу или редактору wish list редактировать информацию о подарке.

### FR-012
Система должна позволять владельцу или редактору wish list удалить подарок из wish list.

## Публичный доступ к wish list

### FR-013
Система должна позволять владельцу wish list создать публичную ссылку на wish list.

### FR-014
Система должна позволять неаутентифицированному пользователю просматривать wish list с помощью публичной ссылки.

## Резервирование подарков

### FR-015
Система должна позволять неаутентифицированному пользователю зарезервировать доступный подарок без создания учётной записи.

### FR-016
Система должна позволять зарегистрированному пользователю зарезервировать доступный подарок.

### FR-017
Система должна предотвращать создание новой брони, если подарок уже имеет активную бронь.

## Управление бронью

### FR-018
После успешного резервирования подарка система должна отправлять неаутентифицированному пользователю электронное письмо со ссылкой для управления его бронью.

### FR-019
Система должна позволять неаутентифицированному пользователю отменить свою бронь с помощью ссылки для управления бронью.

### FR-020
Система должна позволять зарегистрированному пользователю просматривать и отменять свои брони непосредственно в приложении.

## Конфиденциальность

### FR-021
Система не должна позволять владельцу или редакторам wish list просматривать информацию о пользователе, забронировавшем подарок.

## Уведомления

### FR-022
Система должна позволять владельцу wish list включать или отключать уведомления о резервировании подарков.

### FR-023
Если уведомления о резервировании включены, система должна отправлять владельцу wish list уведомление после успешного резервирования подарка.

# Нефункциональные требования

## Производительность

### NFR-001
95% запросов к API wishlist должны обрабатываться не более чем за 500 мс при нормальной нагрузке.

## Доступность

### NFR-002
Система должна обеспечивать доступность не менее 99% в течение календарного месяца, за исключением запланированных технических работ.

## Безопасность

### NFR-003
Все данные между клиентским приложением и серверной частью системы должны передаваться по защищённому протоколу HTTPS.

### NFR-004
Токены, используемые для управления бронированиями, должны генерироваться с использованием криптографически безопасного генератора случайных чисел и не должны быть предсказуемыми.

## Масштабируемость

### NFR-006
Система должна поддерживать не менее 500 одновременно активных пользователей без существенного ухудшения производительности основных функций.

## Резервное копирование

### NFR-007
Система должна выполнять автоматическое резервное копирование базы данных не реже одного раза в неделю.
